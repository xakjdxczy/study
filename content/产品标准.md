# 学习站 · 产品标准（全员强制）

**目标**：上线即专业产品——成体系、全面、成熟、有质量；不是草稿堆砌。

适用于 `小学/`、`驾照/`、`阳光英语/` 及后续栏目。写课、审核、部署都按本文件。

---

## 一、产品定位

1. **可正式上线**：页面完整、导航通、手机可读，不是「临时演示」。
2. **成体系**：有大纲、有进度、有入口；模块之间能串成学习路径。
3. **全面**：承诺覆盖的科目/年级要有规划；未做完的必须在入口标「待上线」，禁止空白死链。
4. **成熟**：同一栏目交互与视觉一致；术语统一；错误处理与免责齐全。
5. **有质量**：考点/知识点准确；图文匹配；练习有反馈；过关能检验迁移。

---

## 二、硬门槛（不过不合并 / 不宣布上线）

### A. 内容专业
- 不编造考点、分值、地方细则；不确定就写「以本地 / 课标 / 车管所为准」。
- 分型清晰（如 C1 含离合、C2 不含；年级口吻匹配）。
- 禁止违法违规建议（替考、作弊等）。

### B. 成体系
- 每个栏目有 `大纲.md` + 网页总入口。
- 单课遵循栏目写法标准（小学 / 驾照各自文件）。
- 新课挂进索引；旧占位及时替换。

### C. 可上线体验
- 一屏一事或短屏推进；关键步骤有图/示意。
- 练习可点选 + 即时错因；过关换情境。
- 桌面与手机大致可用（字号、按钮、不横向溢出）。
- 死链、空壳页、半截文案 = 不合格。

### D. 工程与协作
- **一律 Grok Bot 生成并 `git push`**，禁止 Cursor Cloud Agent 写课。
- 推仓后由 leader 审 + 同步 VPS；结果 @ 用户。
- 未过审不得宣称「已上线完成」。

## 题解与总文档锚点（经验强制）

凡有练习/过关题的栏目：

1. 每题反馈必须写清**原因**（对为什么对、错为什么错）。
2. 必须维护一份**规则/知识总览**（全面、分章、稳定锚点）。
3. 每题反馈附链接跳到总览对应章节。

详见 `content/经验-题解锚点.md`。驾照落地见 `驾照/规则总览/`。

---

## 总览深度

知识/规则总览须教材级（场景、做法、禁做、原因、后果、罚则逻辑），禁止提纲充数。驾照见 `content/驾照/规则总览-深度标准.md`。
